Garantías de cada servicio (para el examen)

Servicio / primitivaGarantíaTrampa del examen
SQS estándarAt-least-onceDuplicados son comportamiento esperado, no un bug.
SQS FIFODedupe + ordenMenos throughput; no reemplaza consumidor idempotente.
StartExecution STANDARDIdempotente con mismo name+inputSolo mientras corre. Cerrada → ExecutionAlreadyExists (400). EXPRESS no idempotente.
TransactWriteItemsAtómico, hasta 100 items / 4 MBSi un item falla, ninguno se escribe.
ConditionExpressionGuarda atómica por itemIdeal para transiciones de estado (PENDING → … ) y no-ops.
DynamoDB StreamsEvento por ítem, ordenado, at-least-onceConector natural outbox → SQS/EventBridge.

Patrón outbox en 3 pasos

  1. POST /orders → TransactWriteItems: ítem orders/{orderId} + ítem outbox/{orderId} en la misma transacción.
  2. DynamoDB Streams emite el insert del outbox (at-least-once, ordenado por ítem).
  3. Una Lambda del stream envía el evento a SQS y borra el ítem del outbox (o usa TTL).

Si la transacción falla, el evento nunca existió → sin huérfanas, sin eventos perdidos, sin duplicados de origen.

Cómo se ve un update idempotente

await docClient.send(new UpdateCommand({
  TableName: process.env.ORDERS_TABLE,
  Key: { orderId },
  UpdateExpression: 'SET #status = :new, updatedAt = :t',
  ConditionExpression: '#status = :expected',   // guarda: solo si estaba en el estado esperado
  ExpressionAttributeNames: { '#status': 'status' },
  ExpressionAttributeValues: {
    ':new': 'PAYMENT_CHARGED',
    ':expected': 'INVENTORY_RESERVED',
    ':t': new Date().toISOString(),
  },
}));
// Si el estado actual no coincide -> ConditionalCheckFailedException -> tratar como no-op

Fuentes de verdad

  • Design principles — Serverless Applications Lens: «Design for failures and duplicates».
  • SQS standard queues: at-least-once, copias posibles.
  • StartExecution: idempotente para STANDARD (name+input).
  • Lambda Powertools Idempotency: implementación del patrón de idempotency key.
  • TransactWriteItems: escritura atómica multi-item.
